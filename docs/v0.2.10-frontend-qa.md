# v0.2.10 Frontend QA

Date: 2026-08-28

This record covers active browser testing of the v0.2.10 frontend against the
real Rust server and de-identified DICOM fixtures. It is a release-readiness
record, not a clinical validation.

## Environment

- macOS, Codex in-app Chromium browser
- Debug Rust binary with the production Vite bundle embedded by `rust-embed`
- Committed `tests/fixtures` corpus: 8 loaded DICOM objects
- Locally generated `dicom-test-suite` compatibility corpus: 87 loaded DICOM
  objects
- Temporary de-identified EMBED CSV used for ROI frame-scope testing

## Automated Gate

`python scripts/check.py core --install` passed after running outside the
restricted loopback sandbox. This covered contract generation, Svelte and
TypeScript checks, 83 frontend behavior tests, the production frontend build,
Rust formatting and strict lints, deterministic fixture regeneration, 251
passing Rust unit/binary/integration tests with 9 expected ignored cases, 55
Python tests, and VS Code TypeScript compilation.

The first sandboxed run failed only because seven tests could not bind local
listeners (`Operation not permitted`). The unrestricted canonical rerun passed.

## Release Blockers Found And Fixed

1. `0c1c1a7` stopped recursive ROI-selection updates that raised Svelte's
   `effect_update_depth_exceeded` during startup.
2. `17a72bf` prevented active-file cleanup from subscribing to and immediately
   clearing later ROI selections.
3. `7c0e2d5` routed frame changes through the normalized navigation sequence so
   per-file multiframe fallback can advance.
4. `9ccba77` excluded incomplete study/series identities from cross-file series
   grouping so unrelated objects cannot be merged.

## Remaining Manual Gate

Compact and narrow responsive drawers were not actively exercised. The in-app
browser's viewport capability did not change the CSS viewport from 1280px,
Chrome was unavailable, and local window-control fallbacks were unavailable.
Automated focus-trap and responsive-state helper coverage passed, but a release
maintainer should still run one compact state (520-979px) and one narrow state
(below 520px), opening and dismissing both Tags and Explorer drawers with
buttons, backdrop, and Escape before tagging v0.2.10.

No other frontend release blockers remain from this pass.
